# 音蔵 — Otogura

Windows 用の音楽プレイヤー（Electron）。
ジャンル → アーティスト → アルバムの 3 カラムで絞り込み、下の一覧から再生します。

**音をしまう蔵。** 名前のとおり、**大きなライブラリのために作りました**。
作者の **171,085 曲 / 387 GB** で実際に測って直しています。

**このアプリは、AI に作らせた見本です。** 経緯は下の「どう作ったか」に書いています。

---

## 使う

### いちばん簡単な方法 — 出来上がったものを落とす

[Releases](https://github.com/xmichinokux/otogura/releases) から、どちらかを落としてください。
**Node.js は要りません。**

| 落とすもの | どんなとき |
|---|---|
| `Otogura-Setup-0.30.0.exe` | **ふつうはこちら。** インストールしてスタートメニューに入ります |
| `Otogura-Portable-0.30.0.exe` | インストールしたくないとき。1 個で動きます（USB でも可） |

### 0.30.0 で変わったこと

**拡大解釈を、強度のスライダーから外して独立した入／切にしました。**

本人の希望:

> 拡大解釈機能ですが、スライダーから外して独立したオンオフボタンにしたいです。
> というのも拡大解釈って広い幅の中から王道的な者同士であったり
> 外した者同士であったり、と種類があるので
> スライダーの外しの部分だけでは条件を満たせないと思いました。
> 王道の拡大解釈が意外と面白いと思ったので、独立したボタンがいいのかなと思いました。

★言われてみれば、これは**別の軸**でした。

```
文脈の強度  … 何を選ぶか（王道のもの ↔ 端のもの）
拡大解釈    … どこまで広げるか（近くで留まる ↔ 遠くまで飛ぶ）
```

0.27.0 では後者を前者に相乗りさせたので、
**「王道のものを、遠くまで広げて選ぶ」が言えませんでした。**

#### 分けたので、4 通りぜんぶ言えます

| | 拡大解釈 切 | 拡大解釈 入 |
|---|---|---|
| **王道** | 王道のものを、近くで | ★**王道のものを、遠くまで広げて** |
| **ふつう** | 混ぜて、近くで | 混ぜて、遠くまで |
| **外す** | 端のものを、近くで | 端のものを、遠くまで広げて |

★**入にしたときの「飛んだ先での選び方」は、文脈の強度が決めます。**

```
王道 × 入   飛んだ先でも、その界隈の王道を選んでください
           遠くへは行くが、行った先では代表格を選ぶ ―― という広げ方

外す × 入   飛んだ先でも、端のほうを選んでください
           遠くへ行ったうえで、そこでも意外なものを選ぶ ―― という広げ方
```

つまみの行に **`🌀 拡大解釈 切`** が出ます。押すと入になり、色が付きます。
既定は切です。入のときも、飛び方に筋を通すこと
（なぜそこへ行ったかを「ひとこと」で言えること）は変えていません。

### 0.29.0 で増えたこと（0.30.0 にも入っています）

**AI の生成を、途中で止められるようになりました。**

本人の希望:

> AIに指示を出した後、生成を途中で止めることってできますか？
> 結構これができないのが地味に不便なので。

走っている間だけ **`⏹ 止める`** が出ます。押せばその場で切れます。

★止めたときは「だめでした」ではなく **「止めました（何も作っていません）」** と出ます。
自分で押したのに壊れたように見えるのが、いちばん困るので。

#### 効くのは 5 つすべて

| | |
|---|---|
| 🎧 一本を組む | 気分から絞るところ・組むところ、どちらも |
| 🌱 辿る | 言葉から辿るところ |
| 🏷 ジャンル名をまとめる | |
| ジャンル名無しを埋める | AI に訊く段だけ（手元で決まるぶんは一瞬です） |

#### 実測

遅い窓口を立てて確かめました（★本物の AI には繋いでいません）。

```
止めなければ   30 秒かかる呼び出し
1.5 秒後に止める → ★1.7 秒で返った
```

★**そこまでに使ったぶんは請求されます。** 止めても「ただになる」わけではなく、
**途中で切るだけ**です。長い生成を待たずに済む、というものです。

### 0.28.1 で直したこと（0.30.0 にも入っています）

**手でジャンルを直しても、AI の手直しが上書きし続けていました。**

本人の報告:

> ジャンルをまとめたタブの中でタグ編集（ジャンルの編集）をすると
> ジャンルをまとめたタブ内で反映されなかったので反映したいです。
> オリジナルのタブの方へは反映を確認しました。
> （あ、ジャンル名無しを変更しました）

★**「ジャンル名無し」の曲には、AI で埋めた手直しが載っています。**
手直しは「見るときに重ねる層」なので、その曲のタグを手で直しても、
**重ねる層のほうが勝ち続けていました。**
mp3 も覚え書きも新しい値になっているのに、画面では古い値のまま ―― です。

本体を 3 回立ち上げて確かめた、直す前の姿:

```
AI の手直しで  ジャンル名無し → Punk
手で直すと      Punk → Hardcore
画面に出るのは  ★Punk のまま
```

**手で直したほうが新しく、意図もはっきりしています。手を勝たせました。**
タグを書いたら、その曲のその欄の手直しは外します。

```
AI の手直しのあと         Punk
手で Hardcore に直した     Hardcore
★立ち上げ直したあと        Hardcore（手の直しが残る）
```

★外すのは**書いた欄だけ**です。
アーティストだけ直したのにジャンルの手直しまで消えるのは、
頼んでいないことをしたことになるので。

### 0.28.0 で増えたこと（0.30.0 にも入っています）

**打った文の履歴が残るようになりました。**

本人の希望:

> 一回使ったら入力欄の文字は消えてほしいと思う反面、
> 同じ条件でどんなのできるかな？と試そうとする自分もいて
> イチイチ文字が消えるのが面倒くさいと思います。
> 入力欄の履歴が残って入力欄をクリックするとしたに履歴が表示される、
> みたいな機能があればいいのかな？と思ったんですが、どうですか？
> ちなみに、履歴は消したいとも思うので履歴を消すなにかもほしいのですが。

**入力欄をクリックすると、下に履歴が出ます。** 押せばその文が入ります。
🎧 の気分と 🌱 の言葉は、別々に覚えます。

★**組めたとき・辿れたときだけ**覚えます。だめだった文は残しません。
★同じ文を何度試しても増えません。**上に来るだけ**です。
★20 件までで、古いものから落ちていきます。

#### 消し方は 2 通り

| | |
|---|---|
| 1 件だけ | その行の右の `✕` |
| まとめて | 一番下の「この履歴を全部消す（N 件）」 |

★履歴は `履歴.json` という**別のファイル**に置いてあります。
消しても、ほかの設定を巻き込みません。

#### 「欄が消える」のはそのままです

組めたら欄は空になります（0.15.2 からの動き）。
**履歴があれば戻すのは 1 クリック**なので、
「消えてほしい」と「また使いたい」が両方かないます。

#### ★設定が書けたかを確かめるようにしました

これは別件の用心です。実地で、`settings.json` が 5 日間まったく
更新されていないのに、同じ置き場の `手直し.json` は書けている、
という状態が見つかりました。コードは同じ形で、原因は突き止められていません。

**分からないものを黙らせないため**、設定を書いたあとに読み返して、
中身が合わなければ画面に出すようにしました。

### 0.27.1 で直したこと（0.30.0 にも入っています）

**「どうやってリセットするんだ？」を直しました。**

本人の報告:

> 「ジャンル/アーティスト/アルバム」タブと自分で生成した「ジャンルタブ」があり、
> プレイリストの「ライブラリ」ボタンもあって「どうやってリセットするんだ？」となります。
> プレイリストが生成されたらジャンルの選択は一度リセットされることと、
> 上のカラムのタブを押したらプレイリストは閉じて
> ライブラリのリストが表示されたらいいのかなと思いました。

★タブが増えたぶん、外す場所も増えていました。
**隠れているタブの絞り込みも効く作り**なので、見えている列を「すべて」に
戻しても、まだ絞られていることがあります。それが分かりにくさの正体でした。

直したのは 3 つです。

**① 一本を組んだら、絞り込みを外します。**
絞り込みは「この一本を組むための指定」でした。組んだら役目は終わりです。

**② カラムのタブを押したら、再生リストを閉じてライブラリに戻ります。**
これで「カラムを触る＝ライブラリを見ている」に揃います。
前は、再生リストを開いたままカラムを触れてしまい、
絞ったのに一覧が変わらない（開いた一本が出ている）ことがありました。

**③ 何か絞っているときだけ、`✕ 絞りを外す（3）` が出ます。**
★数には**隠れているタブのぶんも入ります。** 一度押せば全部外れます。

★外し方は 1 か所にまとめました。絞る欄を足したときに
「1 つだけ外れない」が起きないようにしてあります
（同じ形の事故を、0.26.1 のボタンで一度やっています）。

### 0.27.0 で変わったこと（0.30.0 にも入っています）

**① ボタンを「🛠 整える」にたたみました。**

> ボタンが多くて AI の指示欄をあっぱくしてるのでべつのどこかにまとめたいです。
> 一度使ったらあまり使わない機能なので

表に出るのは **🎧 一本を組む** と **🌱 辿る** だけになりました。
ジャンル名をまとめる・ジャンル名無しを埋める・手直しの出し入れは、
右端の **🛠 整える ▼** の中です。既定では閉じています。

**② イントロを選ばなくなりました。**

> 高確率でアルバム収録1曲めのインストを1曲目に選ぶことです。

原因は頼み文のこの 1 行でした。

```
・ただ合う曲を並べるのではなく、流れを作ってください。
　入りは軽く、中盤で上げて、終わりは落ち着かせる ―― といった起伏を意識する
```

**「入りは軽く」と言われた AI は、素直にイントロを頭へ置きます。**

候補の側でも落とすようにしました。**題名が丸ごと Intro / Outro /
Interlude などのときだけ**です。実測で 602 曲（0.71%）。

```
落ちるもの  Intro 417／Outro 104／Interlude 44／Epilogue 11／Prelude 7 …
            ★そのうち 61% は盤の 1 曲目

落ちないもの Prelude To Extinction／Intro/Say Goodbye／Overture 1948
```

★長さでは切っていません。この蔵書は **60 秒未満が 14.2%（12,176 曲）**あり、
グラインドやパワーヴァイオレンスでは 30 秒が**ふつうの曲**だからです。

★一覧からもくじからも外していません。AI に組ませるときの候補から外すだけです。

**③ 「拡大解釈」を、文脈の強度に預けました。**

> プレイリストの後半になるとセレクトするバンドがものすごい拡大解釈になることです。
> これ、めちゃくちゃ面白い機能なので入れたいんですが、
> 王道セレクトでこれをされるとつらいところがあるなと思いました。

②と**同じ 1 行**が原因でした。「起伏を作れ」と言われた AI は、
後半で遠くへ手を伸ばします。しかも強度に関係なく、いつもそう言っていました。

消さずに、強度で切り替えるようにしました。

| 強度 | 後半の広がり方 |
|---|---|
| 王道 | **最後まで同じ文脈を保つ。**1 曲目と最後が地続き |
| やや王道 | 文脈は保つ。軽い起伏だけ |
| ふつう | 起伏をつける。少しだけ離れてよい |
| やや外す | 前半で足場を作り、後半で広げる |
| 外す | ★**後半は遠くの文脈まで飛んでよい。**「そう来たか」と思うところまで |

★飛び方には筋を通させます。なぜそこへ行ったかを「ひとこと」で言えること、
という条件を付けてあります。

### 0.26.1 で直したこと（0.30.0 にも入っています）

**押したあと、一部のボタンがグレーのまま戻らなくなっていました。**

本人の報告:

> ジャンル名をまとめるをやったあと、ジャンル名無しを埋めると
> まとめをやめるのボタンがグレーになって使えなくなりました。
> 立ち上げ直したらボタンが白に戻りました。

原因は、**止める側と戻す側で一覧が別々に書いてあった**ことです。

```
止める … ボタン 9 つ ＋ つまみ 3 つ をまとめて止める（1 か所）
戻す   … ★id を直書きした一覧が 4 か所。どれも中身が違った
```

ボタンを足すたびに 4 か所を直す作りだったので、0.26.0 で足した 4 つ
（まとめをやめる・ジャンル名無しを埋める・手直しを見る・手直しを捨てる）が
どの一覧にも入っていませんでした。

AI の欄は「形が変わったときだけ」作り直すので、画面を描き直しても戻りません。
だから**立ち上げ直すまで直らなかった**わけです。

★一覧を 1 か所にまとめ、戻すのも同じ一覧を使うようにしました。
ボタンを足すときは、そこに足すだけで止めるのも戻るのも揃います。

### 0.26.0 で増えたこと（0.30.0 にも入っています）

**① 直したことを、消せる別ファイルに残すようにしました。**

本人の希望:

> ジャンル名をまとめるや自分でタグを直しても立ち上げ直すともとに戻るので
> どこかに記録をセーブして、そのセーブデータを削除や直すことで
> 元通りにすることはできないでしょうか？

`手直し.json` という小さなファイルに残します。
**このファイルを消せば、完全に元通りになります。**

```
{
  "曲": {
    "E:\\iTunes Music\\Balmora\\in oblivion\\01.mp3": {
      "genre": "Metal Core",
      "元": { "genre": "ジャンル名無し" },
      "訳": "AI: 盤名から"
    }
  },
  "直した日": "2026-08-30"
}
```

★**元の値も一緒に残します。** 何を何に変えたのか分かるので、
1 件だけ手で戻すこともできます。

★覚え書き（`library-cache.json`・32 MB）とは**別のファイル**にしました。
覚え書きは走査が作り直すものなので、手で直したものを混ぜると、
走査のたびに消えるかどうかが読めなくなります。
それに 32 MB の中では、開いて直すことすらできません。

欄に **「手直しを見る」**（置き場を開く）と **「手直しを捨てる」** が出ます。
手直しで入ったジャンルの曲は、一覧で曲名のうしろに `✚` が付きます。

**② ジャンルの付いていない曲に、ジャンルを入れられるようにしました。**

> ジャンル名無しのデータがたくさんあってそれをいちいち振り分けるのが大変だから
> AI の力でジャンル名無しのデータを他のジャンルに振り分けられないでしょうか？
> 多少の間違いはありにします（振り分けられないことのほうが面倒なので）。

★測ったら、**半分以上は AI に訊く必要がありませんでした。**

```
ジャンル未定        2,601 曲（蔵書の 3.0%）

  手元で決まる      1,525 曲（59%）★同じ演者の他の曲に付いているジャンル
  AI に訊く         1,076 曲 ／ 160 組 ＝ 1,755 トークン
```

`Leatherface` の 2 曲は、同じ演者の他の **352 曲**が Punk なので、
推測ですらありません。**まず手元で決めて、決まらないぶんだけ AI に訊きます。**
安く、速く、確かになります。

見てもらう画面では、この 2 つを**分けて**並べます。
どちらを信じるかが違うので、混ぜて見せません。

★AI には「迷っても選んでください」と伝えてあります（ご希望どおり）。
ただし**ジャンル名は手元にあるものからしか選ばせません。**
新しい名前を作られると、カラムが知らない名前で埋まってしまうためです。

### 0.25.0 で増えたこと（0.30.0 にも入っています）

**「自分の音源」―― 自分で録ったものを、くじと AI から外せるようになりました。**

本人の話:

> 自分のバンド1は僕のバンドで作曲途中のデータがたくさんあって
> それが読み込まれてるんです。これはシャッフルの対象にされたくない
> というのがありました。それで、タグなしを表示しないとか、
> そういうことを考えていたという経緯がありました。

★**「タグ無しを隠す」は、この用途に半分しか効いていませんでした。**

```
自分のバンド1 ／ 自分のバンド2 ／ 自分のバンド3 ／ 自分のバンド4   453 曲

  タグ無し   206 曲  ← これだけが消えていた
  タグあり   247 曲  ← ★そのまま、くじにも AI にも入っていた
```

iTunes の頃にタグが付いてしまったものが半分あり、そこが素通りしていました。

#### 使い方

一覧でその演者の曲を 1 曲でも選ぶと、**「◯◯ を自分の音源にする（N 曲）」**が出ます。
1 曲選べば、その演者ぜんぶが入ります。

| | |
|---|---|
| 一覧 | **出ます。押せば鳴ります**（`✎` が付きます） |
| シャッフル | 入りません |
| AI DJ・Resonance の候補 | 入りません |
| 曲そのもの | **消えません。いつでも戻せます** |

「聴きたくない」ではなく「不意に流れてほしくない」ためのものなので、
一覧からは消しません。探せば聴けます。

#### ★覚えるのは演者名です

曲のパスではありません。パスで覚えると、走査し直したときや
新しく録ったぶんが、また混ざってしまいます。
実測でも、演者名なら 453 曲すべて拾えました（フォルダだと 451 曲でした）。

★**完全一致**で見ます。部分一致にすると、こうなります。

```
「自分のバンド3」で当てると…

  自分のバンド3          17 曲  ← 本人のバンド
  名前を含む別のバンド  10 曲  ← ★イタリアのデスメタル。巻き込んではいけない
```

#### 0.24.1 の「盤の多い演者＝王道」も、これで直ります

`自分のバンド1` は録った回ごとに盤が分かれていて **20 枚**あり、
0.24.1 はそれを「長く作っている＝王道」と読んでいました。
自分の音源は候補に入らなくなるので、王道の判定にも効かなくなります。

### 0.24.1 で直したこと（0.30.0 にも入っています）

**文脈の強度の足場を、曲数から「作品数 → 曲数」に変えました。**

本人の指摘:

> 文脈の強度を曲数で調べるってしましたが、曲数の多いグラインドコアだと
> それが効かなくて曲数の多いマニアックなバンドが王道に入ってきました。
> そこで、アルバムの数や作品数の数を調べてから曲数を調べた方が
> いいのではないか？と思いました。

★測ったら、指摘の通りでした。**曲数は盤の作りに引きずられます。**

```
1 枚あたり何曲入っているか（ジャンルごと）

  14.6 曲/枚   Gore Metal
  11.9 曲/枚   Grindcore
   8.3 曲/枚   Hardcore
   5.4 曲/枚   Powerviolence
```

同じ「100 曲」でも、ジャンルによって意味が 3 倍近く違います。
さらにディスコグラフィ盤は、**1 枚に 110 曲**入っていることがあります。

```
ジャンル「Hardcore」… 曲数の上位 20 組と作品数の上位 20 組で
                      重なるのは 6 組だけ（30%）

  曲数だと上位に来ていた     Larm        75 曲 / 1 枚
                            Los Crudos  74 曲 / 1 枚   ★どちらも編集盤
  作品数だと上位に来る       自分のバンド1  20 枚
                            Gehenna         10 枚   ★長く作っている
```

### ソースから動かす

#### 1. 用意する

[Node.js](https://nodejs.org/) が要ります（18 以上）。

```
git clone https://github.com/xmichinokux/otogura.git
cd otogura
npm install
```

#### 2. デスクトップにアイコンを作る（おすすめ）

**`デスクトップにアイコンを作る.bat` を一度ダブルクリック**してください。

デスクトップに「音蔵」のアイコンができます。
**そのアイコンから開けば、黒い窓は一瞬も出ません。**

<img src="icon.png" width="72" alt="アイコン">

スタートメニューに置きたいときは、できたアイコンを右クリック →
「スタートメニューにピン留めする」。

★アイコンの絵は `tools/make-icon.js` が作っています。
画像ファイルを直に置かず、**作り直せる形**にしてあります
（色や形を変えたいときは、そこを直して `node tools/make-icon.js`）。

#### 2'. アイコンを作らずに起動する

**`起動.bat` をダブルクリック**でも開きます（黒い窓が一瞬出ます）。

コマンドで動かす場合はこちら。

```
npm start
```

★どれも中身は同じで、`electron.exe` を直に呼んでいます。
`npm start` を経由すると間に窓がもう 1 枚挟まり、
**それを閉じたときにアプリごと落ちます。**

## 3. 音楽を登録する

下端の**「フォルダを追加」**から、音楽の入ったフォルダを選びます。

拾うのは **`.mp3` `.m4a` `.wav` `.flac`** です。
CD からの取り込み機は、MP3 のつもりでも `.m4a` で書き出すものがあります
（本人の機械がそうでした。詳しくは `src/library.js` の `拾う拡張子`）。

★**aiff と m4p は拾いません。** 実測で鳴らなかったからです
（m4p は iTunes の DRM 付き）。**鳴ることを確かめた形式だけ**を並べています。

★**wav はタグをほとんど持ちません**（手元の 1,268 件中、タグがあったのは 44 件）。
足すと「タグなし」が一気に増えますが、既定の「タグ無しを隠す」が入っていれば見えません。

★**100 MB を超える曲は、音量そろえを測りません。**
測定はファイル全体をメモリに載せるので、大きい wav では持ちません
（実測: 1,095 MB の wav でピーク約 2.1 GB・18 秒）。
測らないだけで**再生はできます**。そのときは下端にそう出ます。

★**`.m4a` のうち ALAC（Apple ロスレス）は鳴りません。**
Chromium が対応していないためです（実測: `DEMUXER_ERROR_NO_SUPPORTED_STREAMS`）。

**一覧からは消しません。** 出したうえで、押したときに理由を出します。
持っている曲が黙って消えるほうが困るからです。
自動送りと ⏭ では飛ばしますが、**飛ばした数を画面に出します**。

設定と読み取り結果は、次の場所に保存されます（**音楽ファイルは動かしません**）。

```
C:\Users\（自分）\AppData\Roaming\Otogura\
  settings.json         フォルダ・再生リスト・音量など
  library-cache.json    読み取ったタグの覚え書き（2 回目以降が速くなる）
```

★このフォルダ名は**アプリ名から決まります**（Electron の決まり）。
名前を変えると保存先も変わるので、**古い名前で使っていたぶんは初回に引き継ぎます**。
写すだけなので、古いフォルダはそのまま残ります。

| 言葉から辿る | **任意。** 言葉を 1 つ入れると、そこから辿れる音楽を探し、手元にあるものを教えます（API キーが要ります） |
| APIキーを入れる | **任意・既定は切。** 入れると、気分を書いて AI に一本を組ませられます |

### 同じアーティスト・アルバムを続けない

シャッフルは、**直前と同じアーティスト（と同じアルバム）を避けて**選びます。

★**どこで効くか測ってから入れました。** 3,000 回引いて、直前と同じだった割合です。

| 範囲 | 同じアーティスト | 同じアルバム |
|---|---|---|
| 全部 86,044 曲 | 0.1% → 0.0% | 0.0% → 0.0% |
| ジャンル 1 つ 6,048 曲 | 1.5% → 0.0% | 0.7% → 0.0% |
| アルバム 10 枚 101 曲 | 9.3% → 0.2% | 9.3% → 0.2% |
| **アルバム 5 枚 54 曲** | **28.1% → 4.7%** | 19.9% → 1.4% |
| **アルバム 3 枚 35 曲** | **32.5% → 1.6%** | 32.5% → 1.6% |
| **アーティスト 3 人 180 曲** | **36.5% → 0.9%** | 12.2% → 0.2% |

**広いところでは、もともと起きていませんでした。** 効くのは 3 カラムで数枚だけ選んだときです。

★**見るのは直前の 1 曲だけ**にしてあります。窓を広げるほど「くじ」ではなくなるので、
「連続しない」の一番弱い形にとどめました。

★**避けられないときは避けません。** アルバムを 1 枚だけ選べば、候補は全部同じ
アーティスト・同じアルバムです。そこで止めたら、選んだとおりに流れません。
段階的にゆるめます（別のアーティスト → せめて別のアルバム → 避けない）。

★**締め出しません。** 上の測定で、どの範囲でも**全曲が出る**ことを確かめています。

### 一本を組む（任意 ／ 既定は切）

下端の「**🔑 APIキーを入れる**」で API キーを入れると、3 カラムの上に欄が出ます。

```
🎧 [いまの気分を書く]  [一本を組む]     🌱 [言葉を 1 つ入れて辿る]  [辿る]
対象の幅 [──●──] ふつう   選出の量 [──●──] 30 曲
```

**入り口は 2 つあります。** 押す前に、どちらのやり方か決まっています。

| 入り口 | どうなるか |
|---|---|
| 🎧 **気分から** | 書いた気分に合うジャンルに絞り、その中から**一本を組みます** |
| 🌱 **言葉から辿る** | その言葉から辿れる音楽を探し、**手元にあったものを「🌐 響き」タブに集めます** |

★**一本を組むのは 🎧 だけです。** 🌱 は絞り込むところまでで、
そのあとは ▶ か 🔀 で流します（辿った結果そのものが、聴く範囲になります）。

#### つまみ ―― 対象の幅と、選出の量

つまみは **1 組だけ**で、**両方の入り口に効きます**。
2 つの道は、最後は同じところ（一本を組ませる）に出るので、意味が共通になります。

| つまみ | 何が変わるか |
|---|---|
| **対象の幅** | AI に渡す候補の曲数（両方）／ 辿る名前の数（🌱）／ 選ばせるジャンル数（🎧） |
| **選出の量** | 一本を何曲にするか（🎧 だけ。🌱 は一本を組まないので効きません） |

| 目盛 | 候補 | 辿る名前 | ジャンル | 曲数 | 🎧 のお金 | 🌱 のお金 |
|---|---|---|---|---|---|---|
| 1 狭い | 50 曲 | 10 個 | 2 まで | 10 曲 | 約 3.5 円 | 約 6 円 |
| 2 | 100 曲 | 20 個 | 3 まで | 20 曲 | 約 6 円 | 約 8 円 |
| **3 ふつう** | **200 曲** | **35 個** | **5 まで** | **30 曲** | **約 8.3 円** | **約 10 円** |
| 4 | 400 曲 | 55 個 | 8 まで | 50 曲 | 約 12 円 | 約 13 円 |
| 5 広い | 800 曲 | 90 個 | 12 まで | 80 曲 | 約 24 円 | 約 18 円 |

★🌱 は 0.18.0 で高くなりました。**出るバンドを増やすため**に、
AI に見せる演者を 150 組 → 800 組、辿る名前を 21 → 35 個にしたためです。
（それでも一本を組まないので、通信は 1 往復です）
「候補」と「曲数」は 🎧 にだけかかります。

★**真ん中が、これまでの値です。** つまみを触らなければ動きは変わりません。

★**上を 800 曲で止めたのは、費用ではなく効きが鈍るからです。**
候補を増やすほど良い一本になるわけではなく、AI が見渡す量が増えるだけで、
1 曲あたりの吟味は薄くなります。

★**幅を狭く・量を多くすると、候補が足りなくなります。**
（候補 50 曲から 80 曲は取れません）そのときは候補の数まで減らし、
**減らしたことを画面に出します。** 黙って短い一本にはしません。

★お金は**目安**です。曲名やアーティスト名の長さで少し前後しますし、
料金も為替も変わります（Opus 5 の 100 万トークンあたり $5 / $25 を 150 円/ドルで換算）。

★**一本ができても、勝手には流れません。** 再生リストができるだけです。
聴くときは ▶ を押してください。

### AI は曲を選びません。絞り込みを選びます

```
書いた言葉
   ↓
3 カラムがその状態になる → 下の一覧が絞られる → そこから一本を組む
```

そうしている理由が 3 つあります。**何をしたか画面に見える**（納得できなければ、
そのまま手で直せます）。**無い曲を作られない**（返ってきた名前は、実在するか
アプリ側で照合します）。そして**そのあとは、いつものシャッフルが働きます**。

#### ★候補は、演者ごとに 1 曲ずつ引きます

AI には候補 200 曲を渡します。**その 200 曲の選び方が効きます。**

曲を 1 曲ずつ引くと、持っている曲数が多いバンドほど何度も当たります。
すると AI は偏った 200 曲から選ぶことになり、頼み文に「同じアーティストを
続けない」と書いても、**1 曲おきに同じバンドが並んで決まりは守られてしまいます**。

演者を 1 周して 1 曲ずつ取り、足りなければ 2 周目に入ります。
**巡の数が、そのまま「1 人あたり何曲まで」になります。**
同じ人から何曲か取るときは、持っている盤を 1 枚ずつ回ります。

| 場面 | 同じ演者の最多（前 → いま） |
|---|---|
| 全部 85,327 曲 | 2.2 曲 → **1.0 曲** |
| Hardcore 12,537 曲 | 4.4 曲 → **1.0 曲** |
| 演者 30 人 5,263 曲 | 17.8 曲 → **7.0 曲** |
| 演者 5 人 1,667 曲 | 53.4 曲 → **40.0 曲** |

★**狭いところでは下限まで下がっています。** 5 人しかいなければ 200 曲は必ず
重なります。**避けられないときは避けません** ―― シャッフルと同じ考え方です。

★**くじは今までどおり**（再生回数が少ないほど重い）。引くのがその演者の中に
なっただけなので、「忘れている曲が候補に入りやすい」性格はそのままです。

★組んだあと、**何組が重なったかを画面に出します。** 黙って済ませると
「まだ直っていない」ようにしか見えないので。

### 確かめる候補（手元で見つからなかった名前）

```
🌐 3 組・120 曲   [辿った言葉（21）] [✎] [×]   [▶ 確かめる候補 12]   [× 全部外す]
```

押すと開きます。**当たり（鳴らせる曲）が主で、こちらは脇**なので、たたんであります。

#### ★当たりと外れで、照合の厳しさを変えています

| | 何に当てるか | なぜ |
|---|---|---|
| **当たり**（曲を鳴らす側） | 演者の完全一致だけ。**厳しく** | 違う曲を鳴らすほうが困るので |
| **確かめる候補**（持っていないと言う側） | 演者・盤名・曲名に部分一致。**緩く** | 持っているのに買いに行かせるのが一番困るので |

同じ判定をそのまま裏返すと、**アルバム名や曲名としてしか持っていないもの、
コンピレーションで持っているものが、全部「持っていない」に化けます。**

実測（86,044 曲。名前の 4 分の 3 は何らかの形で持っている作り）:

```
名前  22 個 … 厳しいと 15 個が「無い」 → 緩くすると 5 個（10 個は持っていた）
名前 150 個 … 厳しいと 110 個が「無い」 → 緩くすると 37 個
```

★**間違えるなら「持っている」側に間違えます。** 短い名前は盤名や曲名に紛れて
「持っている」に倒れますが、それでよいと決めました。
持っていないものを見落とすより、持っているのに買わせるほうが困るからです。

#### ★「買い物リスト」としては出しません

見つからなかった名前には、**3 種類が混ざっていて、見た目では区別がつきません。**

| | |
|---|---|
| ① | 本当に持っていない |
| ② | 持っているが、名前の書かれ方が違う |
| ③ | AI が実在しないものを出した |

だから「確かめる候補」と呼んでいます。**買う・落とす仕掛けは置いていません。**

#### depth で意味が変わります

| 深さ | 意味 |
|---|---|
| 1 | 入口を持っていない（意外な穴） |
| 3 以上 | まだ辿り着いていない場所（探索の先端） |

並びは当たりと同じで**重い順**（深く・新しいほど上）。

★**JSON に足りない欄はありませんでした。** name / depth / description と、
木ごとの keyword / savedAt だけで足ります。Resonance 側の変更は要りません。

### ★`name` は artist だけに当てます（実測で決めました）

木のノード名を、曲の何と突き合わせるか。実物（木 7 本・147 ノード）と
ライブラリ 86,044 曲で数えて決めました。

| 当てる先 | 当たった music ノード |
|---|---:|
| **artist だけ** | **22 個** |
| artist + album | 22 個（**album を足しても増えない**） |
| 3 つ全部 | 22 個（**title を足しても増えない**） |

`title` を足すと全体では 13 個増えますが、中身は**全部 music 以外の偶然の同名**でした。

```
ある思想の名前   [other] 曲名として 2 曲
ある芸術家の名前 [art]   曲名として 1 曲
ある場所の名前   [place] 曲名として 1 曲
ある映画の題名   [movie] 曲名として 5 曲
ある映画の題名   [movie] 盤として  10 曲
```

曲名は短い普通の言葉が多く、**別のものと偶然一致します**。当たっても意味がありません。
**`genre` が `music` のノードだけ**を拾います。

### 重みのつけ方

**深いほど強く、新しいほど強く**しています。

- 深さ 0〜3 で 1〜4 倍（遠いところの当たりのほうが、発見として面白いので）
- 新しさは 60 日で半分になる緩やかな減り方（急に切ると古い木が死ぬので）
- 同じ名前が 2 本の木にあれば、**重いほうの理由**を採ります

名前ごとに全曲を探すと 22 倍になるので、曲の側を 1 回なめて引いています。

**消えるのはこの控えだけ**です。

★消すときは「🔑 APIキーを消す」（同じボタンです）を押してください。消えるのはキーのファイルだけです。

キーは [console.anthropic.com](https://console.anthropic.com) で作れます。

「聴きたくない曲」ではなく「**不意に流れてほしくない曲**」のための仕組みなので。

### シャッフルの対象は、いま絞り込んでいる範囲

3 カラムでアーティストやアルバムを選べば、**その中でシャッフル**します。
選び直せば、**止めずにそのまま**対象が変わります。何も選んでいなければ全曲が対象です。

★以前は「押した時点の一覧」を覚える作りでした。
再生中に絞り込みを変えても次の曲が変わらないように、という意図でしたが、
**全体シャッフルに戻すのに一度止める必要があり**、本人から作り直しの希望が出ました（2026-08-29）。

★一覧は 2,000 行までしか描きませんが、**対象はそこで切りません**。
「見えている 2,000 曲」ではなく「いま絞り込んでいる範囲」が対象です。

### ★ファイルは消しません

一覧の「削除」は**一覧から外すだけ**で、ファイルそのものは残ります。
このアプリのコードには、ファイルを消す処理を**一行も書いていません**。

唯一の例外はタグの編集で、これだけはファイルを書き換えます。
そのときも、**渡した欄以外のタグは触りません**（`node-id3` の `update` を使い、
`write` は使わない）。音のデータが変わっていないことは `check-tags.js` で確かめています。

★**タグを書き換えられるのは MP3 だけです。** `node-id3` が ID3 タグ専用のためです。
`.m4a` を選んだときは、書く前に断って飛ばします（**再生と読み取りはできます**）。

|---|---|---|
| 初めて触るファイル | **約 36 ms** | **約 100 分** |
| 一度読んだファイル | 約 1 ms | 約 3 分 |

★**この 2 つを混ぜないでください。** 作者は一度混同しました。
同じ標本で 2 回続けて測り、「設定を変えたら 24 倍速くなった」と読み違えたのです。
実際は **OS がファイルを覚えていただけ**で、設定は関係ありませんでした。
速さを比べるときは、**どちらも初めて触るファイル**で測ってください。

なお、同時に読む本数（8 / 16 / 32 / 64 / 128）も測りましたが、**差はありませんでした**。
待っているのはディスクそのものなので、増やしても速くなりません。

### ★半分は曲ではなかった

作者のライブラリを数えたら、**171,092 件のうち 85,039 件が曲ではありません**でした。

macOS から Windows 系のディスクへコピーすると、本体と対になる小さな付随ファイル
（`._` で始まるもの）ができます。音は入っていません。

- 読み込みに**倍**の時間がかかっていた（103 分 → **52 分**）
- 一覧が埋まって使いものにならなかった

**数えるまで、ただ「曲がたくさんある」ようにしか見えませんでした。**
いまは `._` で始まるものを飛ばします。実際の曲数は **86,057** でした。

### 待たせない工夫

はじめの登録には時間がかかります。ただし:

- **前回の一覧はすぐ出ます**（覚え書きから。待ち時間ゼロ）
- 読み直しは**裏で進みます**。見つかったそばから一覧に出ます
- 進み具合と**残り時間**を下端に出します
- **途中で閉じても、次に開いたとき続きから**進みます
- **途中で止められます**（下を参照）

### ★重くなったら、止められます

大きなライブラリを読み込むと、**ディスクを長く占め続けます**
（作者の 86,000 曲で約 50 分）。CPU ではなくディスクが詰まるので、
ほかのアプリの読み書きまで遅くなります。

走査中は「再スキャン」が「**■ 止める**」に変わります。押せばそこで切り上げます。

★**止めても損はしません。** そこまで読んだぶんは残り、まだ見ていないぶんは
前の記録から補うので、**一覧は減りません**。覚え書きも減りません。
**次に開いたときは続きから**進みます。

★**数えている最中でも止まります。** 大きなライブラリでは数えるだけで
297 秒かかるので（実測）、読み始めてからしか止まらないと、そのあいだ止められません。

★窓を閉じても止まります。走査は本体の中で走っているだけで、
**別のプロセスも常駐する仕掛けもありません**。閉じればプロセスごと終わります。

一覧は一度に 2,000 行までしか描きません（それ以上は上の 3 カラムで絞ってください）。
省いた件数は画面に出ます。

★この 2,000 という数字も**測って決めました**（500 行 = 39 ms / 2,000 行 = 146 ms /
85,000 行 = 5,915 ms）。最初は測らずに 500 と決めていて、絞り込んでも足りませんでした。

## 動作を確かめる

画面を開かずに、計算部分だけを検査できます。

```
npm run test-music     # 検査用の MP3（無音）を作る
npm run check          # 下の 12 本をまとめて走らせる
```

| 検査 | 見ているもの |
|---|---|
| `check-shuffle.js` | シャッフルが、忘れている曲を選ぶか |
| `check-loudness.js` | 曲ごとの音量差をならす計算 |
| `check-playlist.js` | 再生リストの保存・掃除・m3u |
| `check-url.js` | 変な文字を含むパスでも再生できるか |
| `check-tags.js` | タグを書いても**音のデータが変わらない**こと |
| `check-cache.js` | **取り込み忘れ・黙って捨てる catch・画面と本体のつなぎ・名前を変えたときの引き継ぎ** |
| `check-sort.js` | 並び順（作った台 ＋ **手元のライブラリ全曲**） |
| `check-stop.js` | 走査を止めても、**フォルダが無くても**、一覧と覚え書きが減らないこと |
| `check-ai.js` | AI に渡す頼み文と、**返ってきたものの照合** |
| `check-resonance.js` | 響きの木の読み込みと、曲との突き合わせ |
| `check-knob.js` | **つまみが 2 つの道すべてに効くか。候補より多い曲数を頼まないか** |
| `check-ui.js` | 画面を実際に開いて読む（**音蔵を閉じてから走らせてください**） |

★`check-cache.js` は、実際に起きた不具合から生まれました。どれも**動かすまで気づけない**種類です。

| 起きたこと | 見えた症状 |
|---|---|
| 取り込み（import）の 1 行を書き忘れ、`catch` が握りつぶしていた | 直した直後は正しいのに、**開き直すと元に戻る** |
| 画面が「戻せます」と案内する操作が、**どこにも無かった** | 一度外した曲が二度と戻らず、**足し直しても出てこない** |

2 つめは、`preload` に窓口があり、本体に処理もあり、**画面からだけ呼ばれていない**状態でした。
だから検査は**両方向**を見ます ―― 画面が呼ぶものが向こうにあるか、
そして**向こうが出しているものが、すべて呼ばれているか**。

自分のライブラリで走査の速さを測るときはこちら。

```
node check-scan.js "D:/Music"
```

**リポジトリに音楽ファイルは入っていません。**
`npm run test-music` が、その場で無音の MP3 を作ります。

## どう作ったか

このアプリは、**指示を書いた人が一行もコードを書いていません。**

1. **[Kokoro OS](https://kokoro-os-v2.vercel.app) の Baton** で、作りたいものを書き、
   「まだ決まっていないこと」に答えて**指示書**を作った
2. その指示書を **Claude Code** に渡して実装させた
3. 実際に使って出てきた不具合を、そのつど直した

★**指示書が聞き漏らしていたこと**も分かりました。

| 漏れ | 何が起きたか |
|---|---|
| 再生の始め方 | 押す場所が分からず、しばらく再生できなかった |
| 曲が終わったらどうなるか | 次へ・繰り返し・シャッフルが丸ごと抜けていた |
| **扱う曲数** | 4 曲で試して満足し、1,000 曲で画面が崩れ、170,000 曲で落ちた |
| **隠したものの戻し方** | 「隠す」だけ作られ、**戻す操作が無かった**（案内文だけあった） |

この経験をもとに、Baton は「**操作**（どう始めて、どう終わるか）」と
「**量**（何件扱うか）」を聞くようになりました。

コードの中には、**なぜそう書いたか**と**何を間違えたか**が日本語で書いてあります。
`★` の付いた注記が、実際に踏んだ失敗の記録です。
